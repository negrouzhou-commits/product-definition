# product-definition

**产品定义一体机(Product Definition)** — 把"该不该做"→"生成完整蓝图"→"质量门评审"合成一条连续闭环的 Claude Code skill。

## 这是什么

一个从**一个被否决的真实产品立项**(跨境服务商自研 CRM 被副总裁一票否决)沉淀出来的 skill。它把那段教训固化为一条流水线,防止下次立项再踩同一个坑——尤其是**先盘"已有系统/商业软件"再谈自研**这一最前置、却最常被跳过的存在性关。

核心信条:**先过存在性闸(该不该),再造蓝图(怎么做),每步到里程碑立即走质量门(review),不合格回去改,循环到定稿。**

## 三段能力(一入口自动分流)

| 你说 | 走哪 |
|------|------|
| "值不值得做 / 自研还是买 / 已有XX系统还自研吗 / 要不要立项" | **存在性闸**(第 1 章)|
| "生成用户画像 / 痛点 / 业务/产品架构 / 画布 / 旅程 / 指标树" | **蓝图生成**(第 2 章)|
| "评审这份蓝图 / 找硬伤 / 看看定稿行不行" | **质量门**(第 2 章内嵌)|

## 能力详情

1. **存在性闸(该不该做)**:6 问盘查——已有系统/商业软件能否覆盖、独特场景、现成划算否、独有壁垒、增量基准、激励匹配。任一红灯 → 停,转"现成+增量/暂缓"。
2. **蓝图生成(怎么做)**:按序生成七件套——用户画像 → 痛点+基线 → 业务架构 → 用户旅程 → 产品架构 → 商业模式画布 → 指标树。每步有产出模板(见 `templates/`)。
3. **质量门(做得好不好)**:内嵌于生成流程,每步到里程碑即审。产出"通过/不通过 + 具体 must-fix",不过回对应步改。

## 安装

把本目录放进你的 Claude skills 目录:

```bash
# 全局(所有项目可用)
cp -r product-definition ~/.claude/skills/

# 或单项目
cp -r product-definition <你的项目>/.claude/skills/
```

## 与其它开源 PM/产品 skill 的差异

市面上开源的 PM skill 多数是**通用方法论**(RICE 排序、PRD 撰写、指标诊断、教练问答)——面向"怎么把产品管好"。本 skill 差异化在于它是一条**从真实失败提炼的流程闸门**:

| 维度 | 通用 PM skill | 本 skill (product-definition) |
|------|--------------|-------------------------------|
| 回答的问题 | "这个需求怎么做 / 排多高" | **先答"该不该做"(存在性闸)再答"怎么做"** |
| 起点 | 默认该做,直接进入方案 | **先盘已有系统/商业软件覆盖**,不默认自研 |
| 生成 | 单份文档(PRD/画布) | **七件套蓝图**串成一条固定流水线 |
| 审查 | 无,或一次性终审 | **每步里程碑立即走内嵌质量门**,不过回改再审,循环到定稿 |
| 依据 | 通用方法论 | **反例驱动**(被否决立项的教训固化进流程) |
| 场景判断 | 通用 | **内部工具 vs 现成系统**明确分流 |

一句话:**通用 PM skill 教你"把产品做好";本 skill 先拦"做的是不是本就不该做"。** 前者假设资源已投,后者先保护资源不浪费。

## 关于内置案例

SKILL.md 里的反例素材(`docs/立项复盘-自研CRM反例-2026-09-24.md`)和 memory 引用(`crm-ideation-lesson`)来自作者项目,属**示例性引用**。你在自己项目使用时应替换为你的反例/记忆;可复用的是**顺序 + "每步死在哪个门"的提示**,不是那个项目的内容。
